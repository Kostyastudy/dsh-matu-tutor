Guard the HTTP routes with the DSH connection check

The plugin mounted /aptat-api/* straight on ctx.webServer and relied only on
its own token header. Nothing checked Host, Origin, or the browser credential,
so any page open in the user's browser could call the routes. /bootstrap needed
no credential at all and answered with the plugin token, so a single cross-origin
request was enough to take over the whole surface: read project files, read
tutoring chats, compile and run arbitrary code, and submit to APTAT.

Register the routes through ctx.connection.requestRejection, the same guard DSH
applies to its own Web routes, and declare `connection` in inject so the plugin
fails loudly rather than silently running unguarded.

Verified against the running Harness before and after:
  before  GET /aptat-api/bootstrap (no cookie)            200, returns token
  before  GET /aptat-api/bootstrap (Origin: evil.example) 200, returns token
  after   GET /aptat-api/bootstrap (no cookie)            401
  after   GET /aptat-api/bootstrap (Origin: evil.example) 403
DSH's own /api/state answers 401 in the same unauthenticated case, so the
plugin now behaves the same way.
